# Jarvis local voice diagnostics

Deploy `__init__.py`, `analysis.py`, `manifest.json` to `custom_components/jarvis_voice_diagnostics/`, add `jarvis_voice_diagnostics:` to configuration and exclude `sensor.jarvis_hlas_diagnostika` from Recorder. Restart once. Targets installed HA Core 2026.6.4 STT/TTS and native Assist debug APIs; compatibility failures are reported, never called successful tests.

On startup, recording remains disabled. Controlled reference testing runs only when run_self_test is explicitly invoked. Three fixed Czech sentences are synthesized with existing local Piper, decoded to 16 kHz mono signed 16-bit PCM and sent directly to each installed Whisper/Speech-to-Phrase entity and the pre-existing OpenAI STT entity. They are NEVER passed to a conversation agent or executed. Each sample reports expected/actual text, word error and engine time; failure remains failure. Tests are serialized and capped at 60 seconds per engine.

Native Assist capture and timing monitor covers actual microphone runs separately from synthetic tests. Pipeline events yield VAD/capture, STT, conversation and TTS timing; media-player/satellite transitions measure downstream playback separately. A pipeline end never means the physical speaker has finished. Audio metrics include duration, RMS/peak dBFS, clipping and silence. They cannot establish intelligibility without listening to the local WAV or a controlled acoustic test.

Private report: `jarvis_workspace/voice_diagnostics/report.json`. Private native WAVs: its `capture/` subtree, newest five and max 10 MiB; new recordings are disabled automatically after 15 minutes. An already active recording can finish afterward, subject to HA’s five-minute pipeline timeout. Long WAVs retain their full duration while only their first 20 seconds are analyzed. No www exposure or credentials in reports. Only the three fixed synthetic reference samples are sent to the pre-existing OpenAI STT provider during self-test; microphone recordings are not sent by diagnostics. The actual voice pipeline separately uses its selected STT provider. `jarvis_voice_diagnostics.arm_capture` re-arms a 15-minute window; `run_self_test` runs the controlled comparison; `run_companion_test` explicitly invokes cloud conversation regressions. Neither changes the selected pipeline. Boot runs only bounded local probes and a resolution-only inspection of the real room registry. No physical commands or firmware changes.

Tests: `python -m unittest discover -s managed_sources/voice_diagnostics -p 'test_*.py' -v`.
