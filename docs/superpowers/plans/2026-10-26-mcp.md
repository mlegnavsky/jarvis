# Jarvis MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Add an OAuth-protected MCP adapter to existing Jarvis, ready for real-client acceptance.
**Architecture:** aiohttp routes share existing Actions/HAClient/MaintenanceBridge. Local single-client OAuth service persists hashed artifacts and enforces audience/scopes; REST bearer credentials remain separate.
**Tech Stack:** Existing Python 3.12, aiohttp, standard-library SQLite, secrets and hashlib.
**Spec:** docs/superpowers/specs/2026-10-26-mcp-design.md

## Global Constraints
Default disabled. HTTPS configured origin. Exact redirects. PKCE S256. No arbitrary targets. Mutations share durable idempotency. No real credentials/house inventory. No deployed-connection claims.

## Review Focus
- A valid REST token must not authenticate MCP, nor an OAuth token authenticate REST.
- Wrong resource, redirect, client, expired token, reused code/refresh and changed config must fail before effects.
- Browser login requires cookie-bound CSRF and rate limiting.
- Read-only grant must not gain control when options change.
- Mutation retry must preserve existing request key and never duplicate a physical action.
