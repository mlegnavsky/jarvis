# Jarvis Speaker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement the approved conversation and authorization policy in the existing lab controller and a media session module.
**Architecture:** Python event state machine; independent TV volume guard via a transport interface. Acoustic adapters remain mandatory before activation.
**Tech Stack:** Python standard library, unittest.
**Spec:** docs/superpowers/specs/2026-10-30-speaker.md

## Global Constraints
- Lab only; no Green update or production action.
- Jarvisi; follow-up 3 seconds; unknown voices cannot control devices.
- Presentation never enrolls or authorizes. Playback cannot wake or interrupt.
- No hardware latency claims from simulated events.

## Review Focus
- Previous speaker identity must not authorize next utterance.
- Delayed output callbacks after session end must not restart listening.
- Non-finite speaker confidence must fail closed.
- TV restore failures must preserve pending restore values for retry.
- Repeated wake events must not replace original volume snapshots.
