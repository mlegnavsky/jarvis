# Jarvis Speaker — approved conversation requirements

User approved own control layer in Lab only, no changes to Green. Wake phrase
Jarvisi; spoken identity Jarvis with Czech J. Response target <500ms and voice
identification latency must be measured on actual hardware, not promised from
unit tests. HomePod output, immediate interruption on live human speech, three
seconds follow-up after output ends. TV/Apple TV audio is reduced throughout the
conversation, never paused, then restored even after errors. Ignore playback
and echo. Only enrolled, approved voice profiles may control devices. Unknown
voices may introduce themselves but this never grants control or replays an
old command. Reverify each utterance, including follow-ups. Default light room
is microphone's room. Log decisions without retaining raw audio.

Implementation choice: extend existing Python event controller; separate audio
adapters from authorization and media lifecycle. This branch currently has no
microphone transport, acoustic model, speaker enrollment recordings or access
to the laboratory runtime. These remain integration blockers, not simulated
successes. No invented voiceprints; no production device calls during tests.
